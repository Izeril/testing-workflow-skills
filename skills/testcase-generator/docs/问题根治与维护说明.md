# 测试工作流问题根治与维护说明

## 目标

本次治理将“运行成功”定义为：入口真实执行、结构化证据齐全、质量门禁通过、用户报告可读、覆盖边界明确，并有自动化测试证明。控制台退出码为 0 但没有产物，不再视为成功。

## 已建立的固定契约

### CLI 入口

- `scripts/main.py` 必须以 `raise SystemExit(main())` 结束。
- 冒烟测试会真实执行 `python main.py --help`，防止主函数再次漏接。
- 前置检查会验证当前 Python 可执行文件、Python 子进程和 Git；WindowsApps 别名或子进程启动失败会立即阻断。

### 代码分析 Schema

- `technology_coverage` 对外始终是对象，不允许单目标为对象、多目标为列表。
- 多目标明细保存在 `technology_coverage.targets`，聚合字段包括文件、缺口、告警、状态计数和语言计数。
- 下游置信度、影响报告和用户报告只能读取统一后的对象。

### 需求事实与分析门禁

- `project_name` 固定取需求包目录名；需求正文一级标题可能是聚合页面名称，只能保存为 `document_title`，不得覆盖当前需求包标识。
- 分析阶段先生成 `.ai-internal/requirement_facts.json`，再生成用户可见的 `需求分析.md`。
- 核心门禁检查项目标识、业务背景或问题、解决方案、影响范围。
- 任一核心项为空时生成 `.ai-internal/analysis_quality_gate.json` 并阻断，不得用“待补充”填充后宣称分析通过。
- 需求事实同时保存 `tables`、`apis`、`jobs`、`configs`、`rules` 等结构化维度，供需求代码比较器复用。

### 需求—代码—评审证据链

- 代码分析与需求比较统一使用 `requirement-code-auditor`；`code-analyzer` 和 `req-code-comparator` 已归档到 `.codex/skills-archive/`，主入口禁止调用或回退到它们。
- `.ai-internal/requirement_code_comparison.json` 是分析、评审和测试设计共用的对比结果。
- 比较分类固定为：一致、缺失、不一致、额外实现、证据不足。
- 没有代码维度证据时只能标记“证据不足”，不得标记“缺失”。
- 自动评审问题必须同时包含“适用前提”和“证据”。
- SQL 示例仅在存在数据库证据且需求明确涉及 SQL、索引或查询性能时检查。
- 降级策略仅在存在外部依赖证据时检查。
- 回滚方案仅在存在发布、迁移、数据结构或配置变更证据时检查。

### 用户报告和内部数据

- 用户报告只展示业务流程、结构化对比、P1/P2 风险、验收清单和证据位置。
- 分析器原始 JSON、解析器元数据和大量分支明细只保存在 `.ai-internal/`。
- `代码评审报告.md` 必须显示覆盖缺口、Java 降级文件数、分支/基线 SHA 和远程最新性。

### Java 解析降级

- Tree-sitter Java 不可用或解析失败时，Java 文件覆盖状态必须为 `partial`。
- 覆盖记录必须包含 `fallback_reason` 和实际降级引擎。
- 用户报告不得把结构化降级解析描述为完整 AST 分析。

### DOC 转换

- `.doc` 仍按文件头识别 OLE2、MHTML 或 HTML。
- 写入 Markdown 前检查有效内容、乱码、中文保留和表格结构。
- 任一 DOC 转换或质量校验失败都会阻断前置检查，不能只打印警告后继续。

### Git 最新性

- 默认只定向刷新本次所需的开发分支、基线和 UAT 分支，不使用 `--prune`。
- 离线预分析使用 `--no-refresh-remote`，只读取缓存的 `origin/*`，并标注“最新性未验证”。
- 必须保留开发分支 SHA、基线 SHA、merge-base、比较命令和刷新前后引用证据。

## Windows 1385 处理

错误 `CreateProcessWithLogonW 1385` 表示沙箱账户未获准所需登录类型。本机验证表明 Codex 使用的进程创建路径需要：

- 本地组：`CodexSandboxUsers`
- 用户权限：`SeInteractiveLogonRight`（允许本地登录）

这是系统级安全权限，不应由工作流自动修改。修改前必须获得用户或管理员明确授权，应用时保留原有权限项，只追加专用沙箱组。该权限不会自动授予管理员身份，但会扩大沙箱账户的本地登录能力。

若需回滚，从 `SeInteractiveLogonRight` 中移除 `CodexSandboxUsers`，保留修改前的其他主体，并重新验证普通沙箱子进程。

## 回归测试

在 testing-workflow 整包根目录执行：

```powershell
python -m unittest discover testcase-generator/tests -p "test_*.py"
Push-Location requirement-code-auditor
python -m unittest discover -s tests -t . -p "test_*.py"
Pop-Location
python -m unittest discover doc-to-md/tests -p "test_*.py"
python contracts/validate_contracts.py
```

主入口的功能等价测试从测试专用 `skills-archive` 目录只读加载旧引擎作为参照（不随整包分发）；这属于测试范围，活动工作流只使用统一审计器。

重点回归项：

- 活动契约只登记四个包和八个公开入口，旧包不能重新注册为活动依赖。
- 审计器缺失时，即使归档旧包仍在，也必须报告依赖失败。
- CLI `--help` 真实输出。
- 单目标和多目标覆盖 Schema 一致。
- 核心需求事实为空时门禁阻断。
- 无数据库、外部依赖或运维证据时不生成 SQL、降级、回滚误报。
- Java Tree-sitter 降级时覆盖状态为 `partial`。
- DOC 乱码、空内容或表格丢失时不生成 Markdown。
- 用户代码报告不包含原始分析器 JSON。
