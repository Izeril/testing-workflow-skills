# 需求分析提示词

> 此提示词用于 AI 对需求文档进行深度分析，整合代码分析能力

---

## ⛔ 禁止 AI 擅自做决定

| 禁止项 | 说明 | 正确做法 |
|--------|------|---------|
| 禁止假设已读取 | 不假设前置步骤已完成 | 每个步骤按规范重新读取 |
| 禁止简化 Todo | 清单必须完整 | 按规范创建完整清单 |
| 禁止跳过步骤 | 强制项不可跳过 | 必须逐项执行 |
| 禁止自行判断 | 不可判断不重要 | 按流程规范执行 |
| 禁止分析旧需求 | 只分析分割线以上最新需求 | 识别分割线标记 |

---

## 执行前必须创建 Todo 清单

| 序号 | 步骤 | 强制 | 输出 |
|------|------|------|------|
| 0-1 | 项目根目录定位（向上查找 .skill/） | ⭐ | 定位成功或询问用户 |
| 0-2 | 项目初始化检查 | ⭐ | 未初始化则创建知识库 |
| 0-3 | 文档转换检查 | ⭐ | .doc/.pdf → .md |
| 1 | 扫描需求目录所有 MD 文件 | ⭐ | 文件列表 |
| 2 | 识别需求版本（分割线标记） | ⭐ | 提取最新需求 |
| 3 | 综合读取多文档内容 | ⭐ | 需求描述、设计方案、接口文档、提测文档 |
| 4 | 有有效代码目标时执行统一代码分析（含输出层） | 条件执行 | 代码变更与输出证据 |
| 5 | 仅有已完成代码分析时执行需求-代码比较 | 条件执行 | 分类结论或 skipped |
| 6 | 生成需求分析 MD | ⭐ | 输出需求分析.md |
| 7 | 生成代码审查报告 | 推荐 | 输出代码审查报告.md |

## 条件阶段与结果真实性

代码业务影响仅在取得实际变更文件分析证据后执行。没有代码目标时记录 skipped 及原因，不输出空的业务影响报告；代码目标已指定但执行失败时保留 blocked，不降级为无代码。无代码的需求测试设计使用 RQ → TP，代码覆盖检查明确跳过；文件存在、空列表和错误数为0不能作为分析完成的证据。

## 需求文档版本识别规则 ⭐

需求文档中可能包含多个历史版本，需智能识别并**只分析最新需求**：

### 分割线标记识别

| 分割线格式 | 说明 |
|-----------|------|
| `=== 分割线，以上为最新需求 ===` | 常见格式 |
| `==== 分割线 ====` | 变体 |
| `--- 分割线 ---` | 变体 |

### 分析范围

| 情况 | 分析范围 |
|------|----------|
| 有分割线 | 只分析第一个分割线以上的内容 |
| 无分割线 | 分析整个文档 |

### 示例

```
# 20260101-演示数据接口切换数据源    ← 最新需求（分割线以上）
...
=== 分割线，以上为最新需求 ===
# 20250101-演示信息查询接口逻辑优化  ← 旧需求（分割线以下）
```

**AI 只分析**：分割线以上的最新需求内容

## 多文档综合分析规则 ⭐

### 需求目录结构

```
需求目录/
├── xxx-需求描述.doc/.md
├── xxx-设计方案.doc/.md
├── xxx-接口文档.doc/.md
└── xxx-提测文档.doc/.md
```

### 综合分析策略

**必须综合读取目录下所有.md文件**，而不是只分析"需求描述"：

| 文档类型 | 提取重点 |
|---------|---------|
| **需求描述** | 需求背景、目标、核心功能、影响范围 |
| **设计方案** | 技术架构、数据流、异常处理、接口设计、表设计 |
| **接口文档** | 接口URL、入参、出参、错误码 |
| **提测文档** | 涉及服务、表、接口、定时任务、分支信息、风险评估 |

### 执行步骤

```
1. 扫描需求目录下所有 .md 文件
2. 分别读取每份文档内容
3. 从不同文档中提取对应信息：
   - 需求背景、目标 → 从需求描述提取
   - 技术方案、架构 → 从设计方案提取
   - 接口信息 → 从接口文档/提测文档提取
   - 测试环境、分支 → 从提测文档提取
4. 合并所有信息，生成完整的测试分析
```

## 需求分析 MD 结构

```markdown
# 需求分析报告

## 1. 项目信息
- 项目名称：xxx
- 开发分支：xxx（从提测文档提取）
- 风险评估：xxx

## 2. 需求背景
- 问题描述：xxx（从需求描述提取）
- 解决方案：xxx（从设计方案提取）

## 3. 根因分析
（如有，从需求描述提取）

## 4. 涉及范围
- 服务：xxx（从提测文档提取）
- 表：xxx（从提测文档/设计方案提取）
- 接口：xxx（从接口文档/提测文档提取）
- 定时任务：xxx（从提测文档提取）

## 5. 代码变更摘要
（如有代码分析）

### 5.1 SQL 深度分析
- 数据流转：从哪些表读，写入哪些表
- 过滤条件：WHERE/HAVING 条件
- 聚合逻辑：SUM/COUNT/AVG/MAX/MIN
- 分组排序：GROUP BY、ORDER BY

### 5.2 调用链分析
- 方法定义：方法名、参数、返回类型
- 调用关系：A 调用 B 方法
- 入口方法：@XxlJob、@RequestMapping

### 5.3 输出层证据
- 从接口入口追到返回对象和 DTO/VO 字段，记录明确赋值表达式及源码位置。
- MyBatis resultMap 的列到属性映射需单列；未追到接口响应时标为待追踪。
- 比较需求出参时只使用明确标注的输出字段；未完成的返回链不得判为缺失或一致。

### 5.4 业务规则提取
- if/else判断：业务条件、执行动作
- 异常处理：try-catch、异常类型
- 校验规则：参数校验、合法性检查

### 5.5 配置值提取
- @Value注解：配置键、默认值
- 常量定义：public static final
- cron表达式：定时任务时间

### 5.6 流程图
（文本流程图）

## 6. 需求 vs 代码交叉验证
- ✅ 已实现：需求中的功能在代码中实现
- ❌ 未实现：需求中的功能未在代码中找到
- ⚠️ 不一致：需求与代码实现不一致

## 7. 待确认问题
1. xxx
2. xxx
...
```

## 代码分析器调用

通过 testcase-generator/scripts/main.py 的 analysis 阶段，经 cross_skill_adapter.py 调用 requirement-code-auditor/scripts/workflow_api.py 的 extract_business_logic 与 compare_structured。该包内统一维护源码分析、输出层追踪和需求实现比较；主入口继续负责目标 SHA、Git/UAT/Codegraph 门禁、需求事实及业务影响，不依赖独立审计目录产物。代码目标没有完成分析时比较环节记录 skipped；没有目标时需求文档流程继续，已指定目标但分析失败时保留代码环节 blocked，禁止进入代码测试设计。

**分析模块**：

| 分析器 | 文件 | 输出 |
|--------|------|------|
| SQL分析 | sql_analyzer.py | 数据流转、过滤条件、聚合逻辑、分组排序 |
| 调用链分析 | call_chain_analyzer.py | 方法定义、调用关系、入口方法、数据流转路径 |
| 输出层追踪 | output_layer_analyzer.py | 返回对象、DTO/VO 赋值、MyBatis 列映射及未解析缺口 |
| 业务规则提取 | business_rule_extractor.py | if/else判断、异常处理、校验规则、日志模式 |
| 配置提取 | config_extractor.py | @Value注解、常量定义、cron表达式 |
| 流程图生成 | flow_diagram_generator.py | 数据流转图、业务流程图 |

## 规则库匹配

读取通用 rules_config.json 及本机 rules_config.local.json（如有），识别项目类型：

| 规则类型 | 匹配关键词 |
|---------|-----------|
| 通用 | startup, logging, data_integrity, field_mapping, filter_condition, aggregation |
| 定时任务 | normal_execution, exception_handling, retry_mechanism |
| 数据迁移 | migration_integrity, sync_status |
| 分表分片 | routing, auto_create, range_limit |
| 报表统计 | accuracy, performance |
| 接口服务 | input_param, output_field, exception |
| StarRocks | dwd_query, sync_monitor |
| 监控告警 | threshold, notification |

**新项目自动学习**：遇到新项目类型自动添加到规则库

## 执行流程

```
1. 前置检查 → 项目定位 + 初始化 + 文档转换
2. 扫描需求目录 → 列出所有 .md 文件
3. 识别需求版本 → 分割线标记，提取最新需求
4. 综合读取多文档 → 需求描述、设计方案、接口文档、提测文档
5. （如有代码仓库）执行代码分析：
   - SQL 深度分析
   - 调用链分析
   - 业务规则提取
   - 配置值提取
   - 流程图生成
6. 有已完成代码分析时执行需求-代码比较；否则比较环节记录 skipped，已指定目标但分析失败的代码环节保持 blocked
7. 生成需求分析 MD
8. 仅在存在代码分析时生成代码审查报告 MD
```
