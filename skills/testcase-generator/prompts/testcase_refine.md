# 用例细化提示词

> 此提示词用于 AI 将测试点细化为可执行测试用例

---

## ⛔ 禁止 AI 擅自做决定

| 禁止项 | 说明 | 正确做法 |
|--------|------|---------|
| 禁止假设已读取 | 不假设前置步骤已完成 | 每个步骤重新读取 |
| 禁止跳过前置条件 | 必须补充前置条件 | 从需求/技术方案提取 |
| 禁止使用占位符 | 必须数据实例化 | 使用具体测试数据 |
| 禁止添加 TC 编号 | 可导入版无 TC 编号 | 仅使用 [P1/P2] 标记 |

---

## 执行前必须创建 Todo 清单

| 序号 | 步骤 | 强制 |
|------|------|------|
| 1 | 解析评审后 XMind | ⭐ |

| 3 | 读取技术方案 MD | ⭐ |
| 4 | 补充前置条件 | ⭐ |

| 8 | 优先级评定 | ⭐ |
| 9 | 分类占比检查 | ⭐ |
| 10 | 生成测试用例 JSON | ⭐ |
| 11 | 生成测试用例 Excel | ⭐ |
| 12 | 生成可导入版 XMind | ⭐ |

| 输入 | 来源 | 必选 |

## 用例细化规则

### 0. 评审终稿解析

| 规则 | 说明 |
|------|------|
| 先解析评审变更 | 识别 `flag-green` 新增、`flag-red` 删除、标题变更和无标记保留 |
| 生成测试意图卡 | 每个保留测试点先还原验证对象、输入/条件、期望行为和父级模块路径 |
| 证据回填 | 基于需求文档、技术方案、评审报告、代码/SQL证据补齐执行细节 |
| 不确定不硬编 | 证据不足时标记待确认，不编造测试数据、接口或预期结果 |

### 1. 前置条件补充

| 来源 | 提取内容 |
|------|---------|
| 需求文档 | 登录状态、数据状态、配置信息 |
| 技术方案 | 接口参数、数据库状态、定时任务状态 |

### 2. 步骤细化

| 规则 | 说明 |
|------|------|
| 步骤 ≥ 3 个 | 每个用例至少 3 个操作步骤，少于 3 个必须拆分为准备、执行、记录/校验等可操作步骤 |
| 步骤编号 | 使用「1、」「2、」格式 |
| 步骤具体化 | 具体操作对象、具体验证方法 |

### 3. 数据实例化

| 禁止 | 示例 |
|------|------|
| 占位符 | "某客户"、"任意值" |
| 模糊描述 | "查看字段"、"验证结果" |

| 正确 | 示例 |
|------|------|
| 具体数据 | "客户编码：CUST001"、"额度：500000" |
| 具体字段 | "查看额度字段"、"验证返回状态码=200" |

### 4. 步骤与预期对应

```
步骤数 = 预期结果数
每个步骤对应一个预期结果
```

## 优先级评定标准（通用版）

### P1 关键词（满足任一即为 P1）

| 类别 | 关键词 |
|------|--------|
| 异常/错误处理 | 异常、错误、超时、失败、非法、容错、恢复 |
| 核心业务逻辑 | 核心、主流程、关键、检索、查询、计算、校验 |
| 数据完整性 | 完整、准确、一致性、丢失、泄漏、映射、转换 |
| 安全/合规 | 安全、权限、认证、加密、合规、敏感 |
| 系统稳定性 | 崩溃、阻塞、死锁、连接、中断 |
| 接口集成 | 接口、集成、交互、上下游、依赖 |

### P2（默认）

不包含 P1 关键词的测试用例，默认为 P2。

## 分类占比目标

| 分类 | 目标占比 | 检查 |
|------|---------|------|
| 功能测试 | 60%~70% | 偏高需增加异常用例 |
| 集成测试 | 20%~30% | 偏低需加强跨模块用例 |
| 安全测试 | 5%~10% | 缺失需补充安全场景 |
| 性能测试 | 按需 | 需求有性能要求则补充 |

## 可导入版 XMind 结构规范 ⭐

```
2026  ← 根节点（年份）
└── 202605
    └── 20260512
        └── 【项目名称】（从输出目录提取，无外层【】）
            └── <公司> [star-red]
                └── 功能测试
                    ├── 测试用例标题 [P1]
                    │   └── 前置条件：xxx
                    │       ├── 1、操作步骤1
                    │       │   └── 预期结果1
                    │       ├── 2、操作步骤2
                    │       │   └── 预期结果2
                    │       └── ...
                    ├── 测试用例标题 [P2]
                    │   └── 前置条件：xxx
                    │       ├── 1、操作步骤1
                    │       │   └── 预期结果1
                    │       └── ...
                    └── ...
```

### 层级说明

| 层级 | 内容 | 格式 |
|------|------|------|
| 根节点 | 年份 | 2026 |
| 二级 | 年月 | 202605 |
| 三级 | 年月日 | 20260512 |
| 四级 | 项目名称 | 从目录提取，无【】 |
| 五级 | <公司> | 带 `[star-red]` 标记 |
| 六级 | 功能测试 | 固定分类 |
| 七级 | 测试用例标题 | 带 `[P1/P2]` 标记，无 TC 编号 |
| 八级 | 前置条件 | 标题为「前置条件：xxx」 |
| 九级 | 操作步骤 | 编号格式「1、」「2、」 |
| 十级 | 预期结果 | 具体结果描述 |

### XMind 文件格式要求

| 文件 | 格式规范 |
|------|---------|
| content.json | 根节点为数组 `[{sheet}]`，每个节点有 `"class": "attached"` |
| metadata.json | 包含 `dataStructureVersion: "2"`、`creator` 等字段 |
| manifest.json | 包含 `content.json`、`metadata.json`、`Thumbnails/thumbnail.png` |

## 评审标记处理规则

从评审终稿中识别用户标记：

| 标记 | 含义 | 处理方式 |
|------|------|----------|
| 🟢 `flag-green` | 新增测试点 | 执行版中保留 |
| 🔴 `flag-red` | 删除测试点 | 执行版中自动过滤，不生成 |
| ✏️ 标题变更 | 修改测试点 | AI 通过标题比对自动识别 |
| 📄 无标记 | 未变测试点 | 按原标题生成用例 |
